# Zac the Ripper — v2.5 Audit & Roadmap

**Date:** 2026-07-17
**Scope:** Full audit of `v2/` (17,097 lines TS/TSX) across six subsystems: rip core, job queue & library export, encoding & hardware acceleration, CD ripping, platform/observability, and the React renderer.
**Method:** Six parallel deep-read audits with claims verified against the actual code (exact `file:line` refs). Encoding findings were additionally **reproduced against the live toolchain on this machine** (Homebrew ffmpeg 8.0.1, mpv 0.41, macOS Apple Silicon) — items marked *(verified)* were actually executed, not inferred.
**v2.5 goals:** Multi-format disc archival utility (DVD / BD / UHD / audio CD) → simultaneous Plex + Jellyfin export → CDs into Navidrome with full metadata and album-art thumbnails → observability good enough that a Claude session can supervise a running rip from the outside.

---

## Executive summary

The happy path — 8-bit SDR DVD/BD → MakeMKV → VideoToolbox H.264/HEVC → single library — is fundamentally sound and works. Almost everything at the edges is broken, and several of the edges are the point of v2.5:

1. **Process control is built on two broken foundations.** The SIGKILL escalation in `process-runner.ts` can never fire (`child.killed` is set when the signal is *sent*, not when the process dies), so a genuinely hung `makemkvcon` — the exact v1.18.3 deadlock this app exists to defeat — survives every watchdog kill. And job cancellation is broken end-to-end: the UI's Cancel button calls an IPC channel that was never registered, the queue's cancel path never cancels MakeMKV at all, and pipelines overwrite `cancelled` status with `completed`.
2. **Observability is absent.** Logs never touch disk (console + renderer IPC only), debug level is permanently unreachable, child-process output is discarded, progress/phase are never persisted, and there are no crash handlers. `tail -f` has nothing to tail. This is the single biggest gap versus the v2.5 goals.
3. **MakeMKV output parsing is wrong in two load-bearing places.** Stream-info (SINFO) parsing garbles all audio/subtitle metadata, and disc-info (CINFO) parsing types **every disc as DVD** — so BD/UHD failures get misrouted into the DVD-only VOB fallback and disc identity is unstable.
4. **HDR/UHD encoding is broken across the board** *(verified)*: the UHD→1080p downscale dies on an invalid filter arg 100% of the time; H.264 on HDR silently produces banded 8-bit output with no tone mapping; software x264 hard-errors on 10-bit input; and all four color-tagging "fix" blocks are no-ops on ffmpeg 8.
5. **FFV1 "lossless archival" is not lossless** *(verified)*: it force-converts to 4:2:0, misdetects 10-bit sources as 8-bit (truncation), and re-encodes all audio to FLAC — permanently destroying TrueHD/Atmos and DTS:X bitstreams.
6. **The CD→Navidrome pipeline doesn't work end-to-end.** The MusicBrainz disc ID is computed without the required +150 sector offset, so automatic identification essentially never matches; the manual-search fallback never fetches track lists, so albums rip as "Track N" either way; cdparanoia runs without its progress flag so the stall-killer murders slow rips; and a file-exists check then reports the truncated track as success.
7. **Dual Plex+Jellyfin export works structurally but wastefully and imperfectly.** Every extra library gets a full byte-for-byte copy executed **synchronously on the main thread** (UI frozen for minutes); a one-line APFS `COPYFILE_FICLONE` makes copies instant. Plex's default agents never read the NFO metadata; TMDB credits are never requested so NFO cast lists are always empty.
8. **Code health:** `tsc --noEmit` fails with ~34 errors (masked because electron-vite strips types without checking), there is no typecheck script, no linter, no tests, ~500+ lines of dead code (an entire abandoned encode-while-ripping cluster, dead components, dead hooks), and 29 npm audit vulnerabilities (21 high).

Everything above is fixable, most of it cheaply. The roadmap below sequences the work so that safety and observability land first (they de-risk everything else), then correctness, then the v2.5 feature goals.

## Roadmap

Phases are ordered by dependency, not glamour: 0–2 make the app safe to iterate on and observable while it runs; 3–4 make video ripping/encoding correct; 5–7 deliver the v2.5 headline features; 8 hardens. Each phase is independently shippable.

### Phase 0 — Code health baseline

Goal: trustworthy foundations; regressions become visible.

- [ ] Fix all ~34 `tsc --noEmit` errors (mostly `job-queue.ts` TMDB TV narrowing, `connection.ts:54`)
- [ ] Add scripts: `typecheck`, `lint` (eslint + typescript-eslint), `test` (vitest), `check` (all three); run in CI or a pre-commit hook
- [ ] First unit tests over the pure functions where the worst bugs live: MakeMKV robot-output parsing (CINFO/SINFO/PRGV/MSG fixtures), cdparanoia TOC parsing + MusicBrainz discId, encoding-preset arg builders, filename sanitizers
- [ ] Delete dead code: streaming-preview cluster (`makemkv.ts:440-583`, `onFileCreated`, `tail-reader.ts`, `encodeFromPipe` ffmpeg.ts:125-249), `useIpc.ts`, `DiscSetSelector.tsx`, `LogViewer.tsx` + jobs-store log plumbing (or mount it), `kodi-output.ts exportMovie()`, dead preload endpoints, `detectInterlacing`/`detectFramerate` in ffprobe.ts, `DB_QUERY` channel, `migrationsDir`
- [ ] `npm audit` remediation pass; bump version to 2.5.0-dev; README refresh (CD ripping, real feature set)
- [ ] Derive `APP_VERSION` from `app.getVersion()` (constants.ts:4 hand-duplicates package.json; Sidebar/About hardcode "v2.0")

### Phase 1 — Process control & lifecycle safety

Goal: every child process can be killed, cancelled, and cleaned up; nothing orphans.

- [ ] Fix kill escalation: track actual exit via `exit` event (`exited` flag / `child.exitCode === null`), then SIGKILL after grace period — `process-runner.ts:76-83`, `ffmpeg.ts:240-244`; guard double `error`+`exit` dispatch with a `fired` flag
- [ ] Register `job:list`/`job:status`/`job:cancel` IPC handlers backed by the queue (UI Cancel currently rejects — `ProgressPage.tsx:37`, `ActiveJobsPanel.tsx:19`)
- [ ] Wire MakeMKV cancellation: queue holds the MakeMKVService reference and calls `cancelJob` on cancel (`job-queue.ts:1614-1630`)
- [ ] Prefix-match ffmpeg job cancellation (`${jobId}_ep_N`, `${jobId}_extra_N`) like ffmpeg-ripper already does (`ffmpeg.ts:251`; use `jobId + '_'` separator check in ffmpeg-ripper.ts:637)
- [ ] Cooperative cancellation: per-job cancelled flag checked between pipeline phases and inside `ripAllTracks`; `updateJobStatus` refuses to overwrite `cancelled`; treat cancel-kill ffmpeg exits as cancelled not failed; unlink partial outputs
- [ ] `safeSend(window, channel, data)` helper with `isDestroyed()` guards; replace all ~25 raw `webContents.send` sites in job-queue/makemkv/ffmpeg/cd-ripper/preview
- [ ] `before-quit`: kill all tracked children (await brief exit), mark running jobs `interrupted`, close DB; also `requestSingleInstanceLock`
- [ ] Startup reconciliation: stale `running`/`pending` → `failed («interrupted»)`; sweep orphaned `ztr_stage_*`/`ztr_music_*`/`ztr_poster_*`/`ztr_fanart_*` temp artifacts
- [ ] A real queue: serialize rips per drive (replace the shared `rippingInProgress` boolean with per-drive reference counting), bound concurrent encodes (fire-and-forget `executeEncodeJob` currently spawns N×2 ffmpeg processes), `.catch()` on all fired pipelines, prune terminal jobs from the in-memory array
- [ ] Music pipeline goes through the same scheduler (currently fire-and-forget outside it — `job-queue.ts:1373`)

### Phase 2 — Observability for AI supervision (headline v2.5 feature)

Goal: a Claude session (or any external process) can fully reconstruct and supervise app state from disk.

Design:

```
~/Library/Logs/Zac the Ripper/
├── main.log            # human-readable, rotating, level from ZTR_LOG_LEVEL/setting
├── events.jsonl        # structured lifecycle events (machine-readable, append-only)
├── status.json         # atomic snapshot: pid, uptime, drives, active jobs
│                       #   {phase, progress, speed, eta, lastError}, updated ≤5s
└── jobs/
    └── <dbId>-<tool>.log   # full child stdout/stderr transcript per job (makemkv, ffmpeg, cdparanoia)
```

- [ ] JSONL event log: `app_start`, `app_quit`, `disc_detected`, `job_created`, `phase_changed`, `progress` (throttled), `read_error`, `watchdog_kill` (with reason!), `job_completed`, `job_failed`, `job_cancelled`, `heartbeat`
- [ ] File sink in `createLogger` (rotation by size); serialize the `...args` payloads that are currently dropped
- [ ] Crash capture: `uncaughtException`, `unhandledRejection`, `render-process-gone`, `child-process-gone` → synchronous write before exit
- [ ] `setLogLevel` wired to `ZTR_LOG_LEVEL` env + settings row (currently exported, never called — debug is unreachable); child stderr logged at info during rips, full transcript to per-job file
- [ ] Persist progress + phase to the jobs table (throttled ~5s/1%); include phase in `getActiveJobs`; watchdog kill reasons propagate to error messages, DB, and notifications (currently misdiagnosed as "disc may be scratched")
- [ ] Renderer → main log channel (UI errors currently invisible); pid+command tags on process spawn/exit logs
- [ ] `docs/SUPERVISING.md`: the contract for an external Claude session — where the files are, event schema, what healthy vs stalled looks like, how to intervene safely (e.g. `job:cancel` via CLI or killing PIDs from status.json)
- [ ] Notifications for `executeBackupJob`/`executeEncodeJob` (currently silent); structured summary (jobId, duration, files, read errors, partial failures)

### Phase 3 — Disc identification & rip-core correctness

Goal: discs identify correctly, damaged-disc telemetry is honest, fallbacks actually work.

- [ ] Rewrite CINFO parsing: attr 1 → disc type (detect UHD), attr 32 → volume name, attr 2 → title; stable discIds (never device paths — `disc-detection.ts:555,707,820`); prefer OS `drutil` bookType over drive-name inference
- [ ] Rewrite SINFO parsing: dispatch on the Type attr value ("Audio"/"Subtitles"/"Video") per stream, then route attributes by remembered stream type (`disc-detection.ts:1077-1092`)
- [ ] PRGV: use the `total` field for percentage (currently resets to 0 at each operation transition); guard NaN; non-greedy MSG/PRGT quoted-field regexes; quoted-CSV-aware DRV parsing
- [ ] Deadlock watchdog for `backup()` (raw archival capture currently has zero protection); extract shared `watchProcessHealth` util (currently duplicated with diverged constants)
- [ ] Surface partial title failures (`ripTitles` returns success+error today and the error is ignored) in RIP_COMPLETE, notifications, DB
- [ ] `getDiscInfo` guarded during rips (Retry Scan can currently spawn a concurrent `makemkvcon info` against the busy drive); await killed in-flight scan before starting a new one; index drives by MakeMKV slot not array position
- [ ] VOB fallback: count corrupt/dropped packets and report as read errors (currently `discardcorrupt` + reports clean); validation failure = per-VTS failure not a warn; correlate mount point with the actual target drive; fix the empty-tracks stub path (enumerate VTS directly); fix `vtsIndex` progress lag
- [ ] Cache last DiscInfo keyed by fingerprint; `createRipJob` reuses it instead of a fresh 30s+ full rescan inside RIP_START
- [ ] Single-pass MakeMKV rip when all titles selected (per-title spawns re-analyze the disc each time)
- [ ] Rippers return explicit titleId→file mappings; TV episode/extras/encode pairing keys on titleId, never array index (`job-queue.ts:714-717`, `833-851`)
- [ ] Encode to staging, atomic-rename into library on success (failed encodes currently leave corrupt MKVs in the live library); preserve staging on encode failure for retry (hours of ripping currently discarded); queue follow-up encodes **before** staging cleanup (`job-queue.ts:1169-1200`)

### Phase 4 — Encoding & hardware acceleration overhaul

Goal: HDR/UHD correct, FFV1 truly lossless, hwaccel selections that actually work. *(Most items reproduced against ffmpeg 8.0.1.)*

- [ ] HDR→SDR tonemap chain for UHD downscale: `zscale=t=linear:npl=100,tonemap=hable,zscale=m=bt709:t=bt709:p=bt709:r=tv` (or libplacebo) replacing the invalid `colorspace=…iall=bt2020ncl` args
- [ ] H.264 preset: tone-map HDR sources (or auto-switch them to HEVC); `-pix_fmt yuv420p` on the libx264 branch (hard-errors on 10-bit today)
- [ ] Replace all four `-color_primaries`/`-color_trc` output-option blocks with the `setparams` filter (verified: options don't reach the bitstream on ffmpeg 8; setparams works)
- [ ] PAL detection by height ≥576 / fps 25 (untagged PAL DVDs currently converted as NTSC); only apply BT.2020/PQ x265 fallbacks when actually HDR (10-bit SDR currently mislabeled as PQ)
- [ ] Hoist deinterlace decision out of the SD-color branch: interlaced HD (1080i) currently never deinterlaced and hw encoders ignore the interlace flags → combing; skip color conversion on field-woven frames when preserving interlaced; consider `bwdif`
- [ ] FFV1 true archival: pix_fmt derived from source (never force 4:2:0), `-c:a copy` all audio (FLAC only for LPCM), `-coder 1 -context 1`, field-order metadata for interlaced sources, bit depth from `pixelFormat` string (ffprobe omits `bits_per_raw_sample` for 10-bit HEVC)
- [ ] Bit-depth detection from pix_fmt everywhere (`ffprobe.ts:156`); `idet` sampling fallback when field_order is progressive/unknown on SD MPEG-2
- [ ] Probe `ffmpeg -encoders` at startup; filter the hwaccel UI to what exists; implement `auto` (darwin→videotoolbox; currently silently falls through to software); platform-aware default instead of videotoolbox-everywhere
- [ ] Hardware decode: `-hwaccel videotoolbox` when the filter chain allows (UHD HEVC currently software-decoded while VT encodes)
- [ ] NVENC `-rc vbr -b:v 0` with `-cq`; QSV `-b:v 0`; VAAPI device init + `hwupload` (currently fails 100% on Linux)
- [ ] Sane `hevc_quality` default (~60; seeded '95' → enormous files); mkdir output dirs before encode; stderr tail included in encode failure messages; drop `-movflags +faststart`/`-tag:v hvc1` no-ops on MKV; DV/HDR10+ detection with a warn (or prefer remux)
- [ ] Preview: replace the dead mpv `dvd://` path (removed upstream) — either mpv `file://` playback of mounted VOBs, a MakeMKV-streamed preview, or cut the feature for 2.5 and hide the page

## Verification appendix

Encoding claims marked *(verified)* were reproduced on this machine (Homebrew ffmpeg 8.0.1, mpv 0.41, arm64):

- `colorspace=all=bt709:iall=bt2020ncl` → "Unable to parse option value"; colorspace filter rejects smpte2084 input → "Conversion failed!"
- h264_videotoolbox silently accepts PQ 10-bit and emits washed 8-bit; libx264 + `-profile:v high` on 10-bit → exit 234
- `-color_primaries`/`-color_trc` output options verified dropped on ffmpeg 8 (frame props show unknown); `setparams` filter verified working
- ffprobe omits `bits_per_raw_sample` for 10-bit HEVC MKVs (both libx265 and VT outputs)
- AC3→FLAC re-encode in FFV1 preset confirmed; ffv1 encoder natively supports 4:2:2/4:4:4/10-bit (forced 4:2:0 is the preset's doing)
- mpv 0.41: `--dvd-device` "option not found", `dvd://` "No protocol handler"; ffplay `-dvd_device` invalid; Homebrew ffmpeg 8.0.1 built without the dvdvideo demuxer
- `tsc --noEmit`: ~34 errors; `npm audit`: 29 vulnerabilities (21 high)

Six subsystem audit reports (full line-item findings with `file:line` refs) were synthesized into this document; the fix-lists above carry the refs inline.
